# Guarded lesson notes: implementation constraints

The original lesson completion path wrote a card's note even while a skipped answer was protected. Exact text filtering is insufficient: a note can reveal an equivalent answer in different words. The unpublished learning pilot must not expose notes produced while any skipped-answer guard is active.

The fix needs to preserve the learner's own words and mistake records as well as the card note. Delaying only in the current session object is insufficient: ending or replacing a session clears that object, and recovery can observe a session-end event before it observes the cleared session. A separate durable, private deferred-note record should retain the node payload and the associated guarded question identities. It must not be rendered in the vault's ordinary notes or Now view while any associated guard remains unresolved.

The current prototype stores exact skipped-question instances independently of deferred notes and restores them in new study sessions for Ctrl+U retry. It uses atomic writes, merges released notes through `views.notes_update`, and records a publication marker to make replay after a write interruption idempotent. It waits while any durable guard or open question remains. Tests exercise multiple guards, session end and replacement, a parameterised instance, an automatic session saving a lesson note, and interruptions after answer logging and note publication. Standalone Ask pauses before calling a model when a durable guard is active. These checks cover specific flows, not all possible failures or answer disclosures.

## Unavailable retries and cross-idea disclosures

Previously the pause condition was tied partly to retry eligibility. An excluded skipped item could leave its guard active while an unrelated lesson node revealed its answer. Lesson nodes now pause for any outstanding skipped guard, and `test_unavailable_cross_idea_does_not_disclose_skipped_answer` passes. This interim change can block an unavailable question's prerequisites indefinitely, and other surfaces are not fully protected. Matching the answer text alone cannot protect equivalent expressions or paraphrases.

The recovery path needs to separate permission to *attempt the saved question* from permission to *select and grade it as a current bank question*. A plausible design is to save an immutable copy of exactly what was displayed, including any figure bytes and a digest, at presentation time. A learner could attempt that saved instance without removing a chapter exclusion; an unavailable or outdated question would not be graded against an unverified key or affect FSRS. A submitted, nonempty attempt would resolve only its own guard. Older saved questions whose displayed figure was not pinned cannot be reconstructed reliably from a mutable file path and must remain in review rather than silently showing a potentially different figure. Until this recovery exists, pausing all unrelated lessons would protect answers but could prevent the student learning a missing prerequisite. Both safety and that recovery must be tested together, including restart and interrupted writes; neither a blanket pause nor a string filter alone meets the requirement.

`tutorlib.saved_figures` is an isolated first step: it stores bounded, content-addressed copies and checks their digest on read. Tests cover source replacement, tampering and paths outside the vault. It is not connected to presentation, display or recovery, and does not yet prove that a student saw the saved bytes. Other disclosure surfaces and recovery remain open.

An independent review found that the helper originally blocked when asked to read a FIFO. It now opens nonblocking and rejects non-regular files; a subprocess regression checks this. The reviewer also found that containment checks are separate from file opens and are therefore vulnerable to directory or symlink replacement, and that extensionless snapshots are not established to render in Obsidian. Both issues must be resolved before integration. The displayed question must reference the pinned image from its first presentation, rather than copying the source later when it is skipped.

The helper now traverses directories using open descriptors and no-follow flags, and installs files through an exclusive hard link without overwriting an existing snapshot. A regression rejects symlink components even inside the vault. Independent re-review found no direct outside-vault traversal and identified missing directory syncing, now added. It also identified unresolved concurrent directory replacement and in-place source mutation risks. Image format and actual display binding remain unresolved; do not integrate this helper until these are addressed.

An initial ungraded-attempt storage prototype was removed after independent review found that its skip-text denylist accepted some non-attempts, concurrent read-modify-write operations could lose updates, stale deferred notes could resurrect a resolved guard, and atomic rename alone did not guarantee power-loss durability. A future implementation needs the existing single-writer discipline across every mutation, generation-aware reconciliation of notes and sessions, parsed attempt semantics, and an explicit durability policy. No recovery path from that prototype is present in the application.

The existing terminal app holds `Vault.lock` for its lifetime and the command entry points take it per command. That lock is the natural boundary for recovery mutations, but it is not acquired by the deferred-note functions themselves and its documented fallback can run unlocked if locking is unavailable. Any new recovery API must define and enforce its locking precondition; atomic rename alone is not a concurrency lock. The existing response parser recognises a numbered `?` as a skip, but accepts arbitrary text after `=`, including an expression of uncertainty, so parsing by itself cannot establish that an attempt was made. Recovery must present an explicit, honest confirmation of the submitted work and fail closed on recognised skips, without claiming it can infer effort perfectly from text.

Hints now refuse while a skipped-answer guard is active, preventing another open question's hint from disclosing the guarded answer. An initial scheme refusal was removed after review found that the structured-answer UI ignored the error and displayed an empty mark panel. The revised flow withholds the scheme, saves the typed work in the open session, and offers retry or a return to the menu without marking or calling AI. A test checks draft restoration on restart. The scheme leak regression now passes, but feedback and support disclosures and a complete recovery path remain open.

The current prototype can temporarily suspend open and queued questions, retry a skipped item, and restore the questions and saved draft once guards clear. It blocks session end or replacement while work is suspended; the user can cancel suspension if retry is unavailable. Restart before retry is covered. Feedback that could disclose another protected answer is deferred until open and suspended questions clear, and an interruption test covers recovery of a supplied examiner explanation. Short-answer retries with multiple guards or suspended questions are saved without a grade and reopened for marking later; tests cover two guards and interruption after the attempt log. Reopened work is retained if excluded on restart, and a UI confirmation can explicitly restore an excluded question for marking. Unchanged text-only topical questions can be revalidated against a current reviewed bank; changed or unpinned-image questions cannot. A learner can postpone an unavailable saved attempt to the event log, leave the session, and have an eligible text-only attempt offered in a later session. Tests cover identical attempts, failed and interrupted event writes, and eventual marking. Independent review found no further concrete loss or duplication in the single-writer flow; concurrency and power-loss behavior have not been tested. Image-backed postponed attempts require manual review and do not yet have an in-app recovery path. Text-based checks reject known no-knowledge phrases but cannot prove the learner made a genuine attempt. Support and other output paths also need review. This is not a completed recovery flow.

Postponed attempts now appear in a read-only Home screen that shows the learner's saved work without displaying a rubric, answer key or unverified image. Opening it is refused while a question or skipped answer is protected. An image-backed attempt is visible but cannot yet be restored for marking; the screen says its original image needs review. A terminal fixture screenshot was inspected, and independent review found no concrete privacy issue in the normal menu path. This does not verify concurrent changes or establish a complete image-recovery workflow.

When no question is open, all session modes now pause before showing queued questions or other activities while a skipped guard remains. Retrying automatically sets aside queued questions and restores them after the guard clears; a previous awaiting activity is also retained across restart. Focused tests and an independent sequential-flow review cover these paths. Already-open questions still rely on the separate feedback, rubric and hint guards; this does not establish complete protection for every display or arbitrary AI content.

A subsequent scheme-and-screen prototype allowed a structured response to be set aside while retrying the skipped question. Independent review found that a queued batch could strand the screen, replacing a session could discard the saved work, and the AI guard did not protect a parked structured scheme. The prototype was removed; a single-question restart test was insufficient. A replacement needs persistent user work, multiple-open and queued-question handling, and a fail-closed guard for every parked question across all AI and display paths before it can be exposed.

Verification must cover skipped answers in note text, multiple simultaneous guards, an actual attempt versus another skip, restart, session end and replacement, crash recovery at each write boundary, and preservation of previous user edits. Include parameterised question instances and repeated learning of the same idea. The normal unguarded lesson flow and existing Claude/ChatGPT behavior must remain unchanged. Until these cases pass, the preview and experimental learning tutor must not be presented as satisfying the no-answer-leak guarantee.

## Installed bank impact

A read-only inventory of the installed topical bank on 29 October 2026 found 1,532 questions; all 1,532 have at least one image, and 42 have multiple images. Therefore text-only recovery would not solve unavailable retries for that bank. This is a count of the loaded bank, not a count of all source questions. Image snapshots must cover every displayed page and preserve ordering. The existing extensionless helper remains unintegrated and does not yet establish what Obsidian displayed.

The loaded bank references 1,526 distinct figure paths; all use the `.png` extension. The extension alone does not validate the image bytes. An independent design review recommends pinning all pages before the first question view, then using the pinned paths consistently in Terminal/Now and AI image input. Unavailable retries must save ungraded work without changing exclusions or FSRS; old unpinned figures need a separate manual-review or postponement route. Prerequisite lessons cannot safely resume under an outstanding guard without reviewing their content against all protected answers. None of these recommendations is integrated yet.

The unintegrated helper now has a separate PNG capture path that decodes a bounded, single-frame image before storing its exact bytes under a digest with a `.png` suffix. Eleven helper tests pass, including malformed and differently encoded input, source replacement and snapshot tampering; ten installed bank images were copied into a disposable directory and recovered byte-for-byte. Independent review noted Pillow is not declared as an installation dependency, so this path cannot be integrated until dependency handling is resolved. A renderable extension and verified read still do not prove that a separate renderer opens the verified bytes; the display-binding race and other previously recorded recovery gaps remain.

`app/requirements.txt` now declares Pillow for fresh terminal-app setup. A disposable new virtual environment installed Pillow 13.0.0 and passed a PNG capture/recovery smoke test; the existing environment has 12.3.0 and passes `pip check`. Twelve helper tests pass, including a missing-library failure that writes no snapshot. Existing ready environments do not automatically reinstall changed requirements: integration must handle a missing library explicitly or arrange a safe upgrade. The separate plugin/CLI environment also needs a dependency strategy. No question display or retry uses this helper yet.

The isolated snapshot helper now accepts an ordered list of up to 32 PNG pages, validates every page before writing any, and caps the combined input at 40 MiB. Tests cover order, duplicate pages and a bad later page, and all 14 helper tests pass. Independent review confirmed that a storage failure after earlier pages were written can still leave unreferenced blobs; safe cleanup needs concurrency-aware garbage collection, not blind deletion. This helper remains unintegrated, and does not yet establish actual display binding or complete retry recovery.

Actual Obsidian 1.14.5 reading-view checks in the disposable pilot vault found that an image linked from `.tutor/state/saved-figures` is reported missing, while the same PNG in `Assets` renders. The unintegrated PNG helper now stores under `Assets/tutor-snapshots`; an actual helper-generated digest path rendered in Obsidian, and all 14 helper tests pass. Existing extensionless private snapshots retain their old format. Earlier experimental PNG snapshots at the old hidden path are not read by the new helper; no migration has been implemented. The new asset path participates in ordinary vault sync and export. Independent scoped review found no new demonstrated traversal or data-loss issue. This visual test does not establish atomic binding between verified bytes and a later renderer read.

A standalone `prepare_question` prototype now makes a copy with ordered captured paths and digest records, leaving source question metadata unchanged. It rejects malformed page lists and a primary image that disagrees with the first page. For an `images`-only question it deliberately assigns its first captured page as `image`, matching the existing public view and allowing the existing single-image AI consumer to see that first page; it does not add multi-image AI support. Twenty-one helper tests pass. The prototype is not called by presentation and its paths can still be replaced before a renderer reads them; it is not a completed recovery feature.

A standalone question verifier now checks the primary path, page-list alignment, every snapshot digest and a 40 MiB total byte limit. Twenty-four helper tests pass, including tampered and missing pages, inconsistent order and combined-size rejection. Independent review identified a necessary limitation: if all figure fields are removed, or both page and digest lists are reordered together, this verifier cannot know the original manifest. A durable binding from the initially presented question to its exact ordered manifest is still required. The verifier is not integrated into retry or display, and the path-based renderer race remains.

The engine now has a text-only ungraded retry prototype for exact saved instances. It leaves exclusions in place and stores a submitted attempt for later judgment without recording an answer or starting the chapter; skipping again does not mark. Tests cover cancellation, later restoration and marking, and interruption after the ungraded event; 140 deferred-note, topical and existing restore-dialog tests passed. Independent review found and prompted fixes for repeated skip marking and repeated deferral. An attempted UI dialog introduced ambiguous multi-guard choices and omitted the existing restoration consequence; it was removed after review. The new path is therefore not available in the UI, and image questions remain unsupported. A previous run during the dialog experiment failed the existing restore-dialog test; it passed again after removal.

The terminal retry dialog now offers the ungraded text-only attempt, identifies its question, and keeps the existing explicit warning when restoring an exclusion. The selected ungraded guard is bound to the actual retry. Restoring uses the saved guard digest so different generated variants of one question do not get confused. The user can cancel another skip without marking. A UI test exercises the ungraded option and confirms the exclusion and mark count remain unchanged; engine tests cover multiple guards and variants. The deferred-note, topical and two retry-dialog tests passed 143. Independent scoped review found no remaining concrete issue in this path; the variant check is engine-level, not a complete modal-driven variant test. Image-backed retries, later unavailable marking and the broader protected-prerequisite problem remain open.

The terminal integration test now continues from an ungraded retry through the unavailable-judgment screen and saves that attempt for later without restoring its exclusion. The fixture clears an unrelated pre-existing plan prompt before opening the question; this is a controlled flow, not proof for every interrupted lesson state. Deferred-note, topical, session and full learning-tutor interface suites passed 352 tests together. Image-backed retry and a safe prerequisite-learning path are still outstanding.

A synthetic 80-column terminal capture of the exclusion dialog was inspected. It showed repeated question text when both actions targeted the same question; the dialog now names that question once and says that trying without marking keeps it excluded. The final fixture capture is `ungraded-retry-80.svg`; both retry-dialog tests and 61 deferred-note tests passed. The screenshot covers one short question at one window size, not long questions or all terminal sizes.

A disposable engine integration test manually passes a prepared two-page question into presentation. It verifies the public view and Now note use the two captured paths in order, the existing AI image selector points to the captured first page, and a restart retains the captured bytes after the original source is replaced. The snapshot, AI-context and topical suites passed 110 tests. The existing `_save` writes Now before session state, so integration must address interruption between displaying a new image and durably recording its manifest rather than assuming that call establishes the binding.

A first checkpoint prototype wrote the pinned question into session state before creating its view. Current snapshot, session, topical and deferred-note suites pass 307 tests. Atomic rename in `store.write_text` is not an fsync durability guarantee.

The capture `ungraded-retry-before-60.svg` documents the pre-fix state; 64 deferred-note and retry-dialog tests passed. A post-fix screenshot and smaller window check remain to be done.

## Image-backed recovery: batch checkpoint requirement

An independent review of the current presentation code found that `_questions` numbers a whole batch before `_ask` opens items, while `next` currently removes a queued item before asking it. Pinning and saving each item separately can lose another numbered or queued question after interruption. A safe implementation must stage the complete numbered batch, including unseen queued members, and checkpoint it before exposing any member. Promotion from staged or queued to presented must be durable before rendering; a failed checkpoint must restore the in-memory batch rather than drop an item. Direct `_present`, retries and deferred judgments need the same transition, not a separate unsafe path.

The original source identity must remain available for topical eligibility checks after image paths are replaced. A retry must verify every pinned page and refuse grading when bytes or metadata do not match. Legacy image questions without a pinned original cannot be treated as verified. `verify_question` returns verified bytes, but checking them and then rendering a separately reopened mutable path does not itself prove that the displayed bytes matched; the display boundary needs a verified-byte mechanism or a justified immutable-storage guarantee. Orphaned content-addressed blobs after a failed batch are harmless and must not be deleted if shared.

Required fault tests: interruption after staging and each promotion in a mixed batch; failure to persist a queue; malformed, missing and changed later pages; direct presentation and retry; no lost or duplicate item or grade; and unchanged text-only behavior. The snapshot helper remains unintegrated until these transitions and actual Obsidian and terminal displays are verified.
