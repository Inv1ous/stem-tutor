# STEM Tutor v2.6.1

Prepared 2 November 2026. This release collects the changes since v2.6.0. The existing v2.6.0 tag stays intact;
v2.6.1 gets its own annotated tag when the push commands are run.

## Learning and recovery

- Preserve answers and corrections through interrupted persistence, including Challenge answers and re-marking.
- Reconcile corrected earned marks, mastery, misconception streaks, study days and summaries with durable history.
- Keep new answer-tag revisions and session endings causal across a month-boundary clock rollback, without rewriting
  historical events or guessing arbitrary legacy event order.
- Finish lesson notes before marking an idea done; retry exact note/event bindings after interruptions.
- Count the practice questions actually staged, and preflight every manual paper score before writing any result.

## Screens and AI workers

- Retain numeric drafts, selection, caret and focus after a format refusal. Coalesce the exact same warning within
  its original six-second window; distinct errors and other notifications remain independent.
- Preserve editing through lesson-detail changes and resize. Add keyboard scrolling to shortcut explanations while
  retaining native choice paging and marking controls. Hide inactive solvability controls after an answer.
- Share validated paragraph, heading, list, step, equation and code blocks across Claude, ChatGPT and local replies;
  keep speech separate and reject incomplete documents. Formatting validity is not factual correctness.
- Include the accumulated local MLX, reasoning-strength, preload, image OCR, model-preset and bounded-history work
  described in the changelog. The experimental trained 4B model remains outside presets/selectors because its gates failed.
- Finish explicitly owned Codex/native OCR process groups even when their wrapper exits first. Serialize concurrent
  cleanup, preserve live/indeterminate signal failures for retry, and surface late-launch cleanup denial during close.
  Identity checks and one-shot completion prevent repeated signalling of uncertain/reused groups.

## Storage and extraction

Project workflow configuration is included as currently configured: role/model ladders, a 90% weekly launch cap,
10% Codex/5% Claude reserves, and disabled automatic publication/commits in Refine. These are distinct from the
extraction watch's explicit 20% job floor and final 21% new-start hold. Release preparation starts no workers.

Canonical engine source is `src/tutorlib/`; shared worker support is `src/tutor_workers/`. Distribution paths remain
adapters. Reusable learning resources live in the sibling vault's catalogued Library, preparation and unpublished
builds in Work, and original bytes/rollback journals in Archive. Logs, reports, exports and generated views respect
those preservation boundaries. Optional read-only views warn without losing progress; ordinary save errors remain visible.

All 762 PDFs participated as inputs (760 primary, two auxiliary mark schemes); the DOCX was separately inspected

## Verification and remaining limitations

- Release preparation passed all 24 version, current-release and immutable-guide publication checks. The explicit
  staging list passed a Git add dry run; no files were staged and no commit, tag or push was performed.
- A complete earlier run passed 7,418 cases, with two skips and two existing expected failures.
- The later complete integration recorded 7,448 passes and one Codex cleanup failure. That failure was reproduced
  and fixed; the final cleanup/provider gate passed 288 cases, and the numeric-warning gate passed four cases.
  These separate results do not claim a complete-suite rerun after every final change.
- The aggregate bugwatch board has 250 VERIFIED bugs, two REJECTED bugs and B-080 historically unconfirmed.
  All 41 QOL entries are terminal (40 VERIFIED, one REJECTED). These are cumulative board counts, not a count of
  bugs introduced or fixed solely in this release.
- B-080 lacks the original raw reply and screen, so current clean probes cannot disprove the reported rendering.
  An earlier intermittent cleanup-retention observation also remains documented; later passing controls do not erase it.
- Tests use disposable learner vaults. Source hashes, original learner events and prior review bindings are preserved.

## Push and local data

Use [the v2.6.1 push instructions](../PUSH_V2_6_1.md). The explicit path list commits implementation, tests,
documentation and compatibility adapters. It excludes personal agent settings, unpublished course builds, worker contents,
model weights and Library payloads. The sibling Library/Work/Archive are local workspace data and need their own backup;
a GitHub source checkout alone does not recreate those resources. An external-target symlink records a reference,
not a copy of its destination.
